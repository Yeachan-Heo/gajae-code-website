Start

Getting Started

Install Gajae Code, launch it in a repository or worktree, and run your first reviewable loop.

Requirements

Install the gjc CLI from a supported standalone release, through Bun, or from source. Git is needed only when you choose worktree isolation; a direct local TUI session does not require tmux.

Install

Download a supported standalone release binary, install through Bun, or build from source. Choose the package command below only when using the Bun package path:

UsePackage and command
GJC CLIbun install -g gajae-code
CLI package aliasbun install -g @gajae-code/coding-agent
Embed the runtimebun add @gajae-code/coding-agent
Connect to a live sessionbun add @gajae-code/bridge-client

Install one global CLI package, not both aliases. The two bun add commands are application dependencies, not CLI installers.

Windows (native install)

On Windows 11, install Bun, start a new PowerShell session so PATH refreshes, then install and verify the CLI:

# 1. Install Bun powershell -c "irm bun.sh/install.ps1|iex" # 2. Start a new terminal, then confirm Bun bun --version # 3. Install and verify gjc bun install -g gajae-code gjc --version gjc --smoke-test

bun install -g places the launcher in %USERPROFILE%\.bun\bin. Bun's installer adds that directory to PATH; start a new terminal if gjc is not recognized.

Verify

gjc --version && gjc --smoke-test

Quick start

Start the interactive TUI directly from the checkout you want to work in. For isolated work, create or enter a worktree yourself, then launch the same direct session there.

# Run directly in the current checkout gjc # Or, from a worktree you created or selected cd ../my-task-worktree gjc

Your first loop

Inside a session, use the public workflow surface to go from intent to a proven result:

/skill:deep-interview clarify ambiguous requirements /skill:ralplan build and critique the implementation plan gjc ultragoal create-goals --brief-file <approved-plan> gjc ultragoal complete-goals

Use gjc team ... only when coordinated workers materially help with implementation or verification. Machine controllers should use the SDK WebSocket for direct session control, Coordinator MCP for multi-session automation, or ACP for editor clients—never terminal prompt injection, tail helpers, or pane scraping.

SDK discovery

A running top-level session writes its loopback SDK discovery record to <repo>/.gjc/state/sdk/<sessionId>.json. Read its url and token with an SDK client such as @gajae-code/bridge-client; use Coordinator MCP for multi-session orchestration.

Updates

Startup checks for a newer version without changing your installation. For a recognized Bun global install, run gjc update or reinstall the scoped package at @latest; otherwise update with the original installer or package manager.

gjc update # or, for the Bun global package bun install -g @gajae-code/coding-agent@latest gjc --version && gjc --smoke-test

Configuration

Provider retry budgets live in the global agent configuration at ~/.gjc/agent/config.yml:

retry: requestMaxRetries: 4 streamMaxRetries: 100 maxRetries: 3 maxDelayMs: 300000

requestMaxRetries applies before a stream is established. streamMaxRetries applies only to replay-safe transient stream failures. Invalid auth, unsupported models/providers, malformed requests, context overflow, user aborts, and permanent quota failures remain fail-fast.
